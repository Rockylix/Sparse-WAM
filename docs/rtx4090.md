# RTX 4090: Edge installation and inference

This guide targets a single RTX 4090 with 24 GB VRAM, Linux x86_64 and a
CUDA 13-compatible NVIDIA driver. Run the commands from the repository root.
The instructions describe how to install and validate this checkout; evaluate
reports from your target machine before drawing performance conclusions.

## Environment

Install [uv](https://docs.astral.sh/uv/getting-started/installation/), then clone
the complete source checkout:

```bash
git clone https://github.com/Rockylix/Sparse-WAM.git
cd Sparse-WAM
uv sync --locked --extra edge
uv run --locked --extra edge python -m sparse_wam config --backbone edge
```

`.python-version` selects Python 3.13. The Linux x86_64 lock pins PyTorch
2.14.1+cu130, torchvision 0.29.1+cu130 and cuDNN 9.24.0.43. Keep `--locked --extra edge`
on subsequent `uv run` commands. The default `dev` group includes the test tools.
The root environment supplies offline Edge inference dependencies; inference uses
native cuDNN attention and defaults `COSMOS_TRAINING=0` before importing the framework.

`uv sync` installs Sparse-WAM in editable mode. Keep the complete checkout in place:
the standalone wheel does not bundle the vendored runtimes. If you already have a
matching backend environment, install this checkout with
`python -m pip install -e . --no-deps` instead of replacing that environment's dependencies.

## Model assets and recorded input

Prepare the Edge DROID checkpoint, native Wan VAE and one recorded DROID observation:

```bash
uv run --locked --extra edge python tools/prepare_smoke.py
```

The tool records immutable model and sample revisions and file hashes. Checkpoint
files go under `checkpoints/edge`, the native VAE uses the Hugging Face cache
(`HF_HOME` is respected), and the observation goes to `outputs/smoke/observation.npz`
with a provenance sidecar. Download access may require `HF_TOKEN` with permission
to access the model repositories. Weights and datasets are not bundled with the code.

Use `tools/prepare_smoke.py --help` for custom destinations. With existing assets,
provide a local checkpoint and recorded observation directly to the commands below.
The observation must follow the [DROID input contract](api.md#droid-observation-and-result),
with RGB images, joint/gripper state and a task instruction. A Piper checkpoint or
dataset requires its matching adapter and cannot replace the DROID fixture.

`configs/smoke_edge.json` contains native runtime overrides for offline testing:
auxiliary guardrail models and video decoding are disabled. `configs/edge.json`
is an exported method summary, not a `--native-config` input. Custom native JSON
fields follow the runtime's `RobolabServerArgs`; see [configuration semantics](api.md#offline-edge-inference).

## Offline inference

```bash
uv run --locked --extra edge python examples/infer_edge.py \
  --checkpoint-path checkpoints/edge \
  --observation outputs/smoke/observation.npz \
  --native-config configs/smoke_edge.json \
  --mode sparse --execution eager --seed 0 \
  --output outputs/example/action.npz
```

The example loads the model, runs one recorded observation and writes an `action`
array to the NPZ plus a JSON summary beside it. For the default Edge DROID settings,
the action shape is `[32, 8]`. Choose a new output path for a rerun; the example
refuses to overwrite an existing action file or summary. It does not connect to a robot.

`--mode dense --execution eager` selects the dense control. Sparse-WAM uses the fixed
four-step UniPC schedule, guidance 3 and shift 5, with Core80 + Stable104 retained
future tokens per frame. Python integration through `create_service` or
`SparseWAMRunner` is described in the [API reference](api.md).

## Paired smoke

```bash
uv run --locked --extra edge python tools/benchmark_policy.py \
  --backbone edge --checkpoint-path checkpoints/edge \
  --observation outputs/smoke/observation.npz \
  --native-config configs/smoke_edge.json --smoke \
  --output outputs/smoke/edge.json
```

This runs one Dense/Sparse warmup pair and one measured pair in eager mode, with
matched input and seed within each pair. A failed check writes a failure report
and exits nonzero. Inspect `smoke.passed` and the actual execution counters using
the [acceptance criteria](validation.md#model-smoke). A single measured pair checks
execution and finite outputs; it is not a latency distribution or a task-success test.

## Paired benchmark

First measure Dense eager against Sparse eager on the same recorded observation:

```bash
uv run --locked --extra edge python tools/benchmark_policy.py \
  --backbone edge --checkpoint-path checkpoints/edge \
  --observation outputs/smoke/observation.npz \
  --native-config configs/smoke_edge.json \
  --execution eager --warmup 3 --repeats 20 --seed 0 \
  --output outputs/benchmarks/edge_eager.json
```

For Dense eager against Sparse with Torch Compile and compiler-managed CUDA Graphs:

```bash
uv run --locked --extra edge python tools/benchmark_policy.py \
  --backbone edge --checkpoint-path checkpoints/edge \
  --observation outputs/smoke/observation.npz \
  --native-config configs/smoke_edge.json \
  --execution compile-graph --dense-eager \
  --warmup 3 --repeats 20 --seed 0 \
  --output outputs/benchmarks/edge_compile_graph.json
```

The second comparison measures the joint effect of sparsity and compilation.
Graphs are managed per compiled layer/function, not as one graph around the sampler.
Check actual replay counts and keep cold compilation/prefill separate from warmed
measurements. Evaluate eager first, then compile and compile-graph on the target device.

Reports include mean/median/P90, per-pair action MSE, memory usage, token counts,
Graph replays and [reproduction metadata](api.md#benchmark-provenance). Timing covers
`service.infer`: preprocessing, generation and action postprocessing. Model loading
and warmup are excluded; the fixture disables future-video decoding. Keep this scope
explicit when comparing results with generation-only measurements. Use a new output
path for each benchmark to retain earlier reports. Results remain under the ignored
`outputs/` directory.

## Optional WebSocket service

Offline inference does not require OpenPI. To use the optional WebSocket entry point,
install its transport in the prepared Edge environment. These package versions are
recorded in the vendored Edge lock:

```bash
uv pip install --python .venv/bin/python openpi-server==0.1.0 openpi-client==0.1.2
.venv/bin/python -m sparse_wam serve \
  --backbone edge --checkpoint-path checkpoints/edge \
  --native-config configs/smoke_edge.json \
  --mode sparse --execution eager \
  --host 127.0.0.1 --port 8000 --seed 0
```

Use the environment's Python directly after adding the optional transport; a new
`uv sync` can remove packages outside the selected dependency groups. An existing
compatible full OpenPI installation is also supported. The command above uses the
offline fixture settings for local evaluation; supply your own native JSON and its
required auxiliary model assets for other service configurations. The package exposes
a WebSocket policy service, not a REST API. Each model serves inference serially.

## Nano environment note

Nano needs matching framework/CUDA dependencies, checkpoint, VAE and tokenizer in a
separate environment and process. The root `edge` extra does not provide a Nano
installation or acceptance workflow. Its adapter remains available; see the
[backend differences](backbone_differences.md) for runtime constraints.
